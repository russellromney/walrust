Lightweight SQLite WAL sync to S3 in Rust.

## Why Walrust?

Walrust replicates SQLite to S3. It uses less memory than Litestream:

| Databases | walrust | Litestream | Reduction |
|-----------|---------|------------|-----------|
| 1 | 19 MB | 36 MB | 47% |
| 10 | 19 MB | 55 MB | 65% |
| 100 | 20 MB | 160 MB | 88% |

Walrust's memory remains ~19-20 MB regardless of database count.

### Implementation

- Written in Rust with async/await (tokio)
- No CGO dependencies
- ~8 MB binary size

See [Why Walrust?](/start/why-walrust/) for detailed comparisons and use cases.

## Installation

### CLI (Rust)

```bash
cargo install walrust
```

### Verify

```bash
walrust --version
```

## Set Up Credentials

Configure your S3 credentials. Example for [Tigris](https://tigris.dev) (Fly.io):

```bash
export AWS_ACCESS_KEY_ID=tid_xxxxx
export AWS_SECRET_ACCESS_KEY=tsec_xxxxx
export AWS_ENDPOINT_URL_S3=https://fly.storage.tigris.dev
```

See [S3 Providers](/config/s3-providers/) for AWS, R2, MinIO, and other providers.

## Start the durable watcher

Start the native local-first pipeline. The initial snapshot is admitted to the
fsynced local spool before asynchronous publication:

```bash
walrust watch myapp.db --bucket my-backups
```

Output:
```
native HADBP snapshot admitted to durable local spool ...
uploaded exact native HADBP spool object ...
```

Keep the watcher running with your application. By default, controlled SQLite
checkpoint completion depends on local spool durability, not S3 latency.

## Restore

Restore a database from backup:

```bash
walrust restore myapp.db --bucket my-backups -o restored.db
```

Output:
```
Restoring myapp.db from s3://my-backups/...
  Downloading snapshot... done (1.2 MB)
  Verifying checksum... ✓
✓ Restored to restored.db
```

## Watch Multiple Databases

Sync multiple databases with a single process:

```bash
walrust watch app.db users.db analytics.db --bucket my-backups
```

## Create a Read Replica

Run a local read replica that polls S3 for changes:

```bash
walrust replicate s3://my-backups/myapp.db --local replica.db --interval 5s
```

Output:
```
Replicating s3://my-backups/myapp.db -> replica.db
Poll interval: 5s
Press Ctrl+C to stop

Bootstrapped from snapshot: 1024 pages, TXID 100
[10:30:05] Published native sequence 101 locally
```

The replica auto-bootstraps from the latest snapshot if it doesn't exist, then applies incremental updates.
